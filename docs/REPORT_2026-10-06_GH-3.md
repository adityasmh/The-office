## Workflow file content

```yaml
# fleet-check: PR checks feed the fleet review.
# A red check on a pull request downgrades a fleet PASS to REDO, so this must stay green.
name: fleet-check

on:
  pull_request:
  push:
    branches:
      - "fleet/**"

permissions:
  contents: read

jobs:
  fleet-check:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "24"
          cache: "npm"

      - name: Install dependencies
        run: npm ci

      - name: Type check
        run: npx tsc --noEmit

      - name: Run fleet GitHub check harness
        run: npx tsx ops/github-check.ts
```

## Notes
- Triggers: `pull_request` (any branch) and `push` limited to `fleet/**`, as required.
- Runner `ubuntu-latest`, Node `24`, npm cache enabled on `setup-node`.
- `permissions: contents: read` at workflow level.
- `actions/checkout@v4` and `actions/setup-node@v4` are pinned to the major versions of
  the official actions.
- Per GH-1 note 2, `ops/` is outside the project `tsconfig.json` include, so
  `npx tsc --noEmit` does not type check the harness itself; the workflow therefore
  keeps running `npx tsx ops/github-check.ts` explicitly (final step).

## Open issues
- None blocking. `cache: npm` on `setup-node` expects a lockfile
  (`package-lock.json`); if the repo has none, the step fails. Verify a lockfile is
