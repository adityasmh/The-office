# Order R4-agent-mailbox: agent mailbox: workers on one order can leave each other short messages

## Why
Parallel workers meet only at the final review. A worker that changes an interface cannot tell the worker that uses it. Step A proved live delivery only works into an idle session (see docs/AGENT_TALK_STEP_A.md), so the guaranteed path is a mailbox read at fixed points. Read docs/AGENT_TALK_SPEC.md (Design and Hard limits) first.

## Files
`src/company/fleetTalk.ts` (new), `ops/agent-msg.ts` (new command line tool), `ops/agent-talk-check.ts` (new), `src/company/fleet.ts` (small insertions: the brief builder for a work order, and one trace line when a new message appears), `src/company/envReload.ts` (allow-list line).

## What to build
Env `FLEET_TALK=1` turns it on (default off). Board file `company/fleet/<orderId>/BOARD.jsonl`, append-only, one JSON object per line `{id, ts, from, to, kind, text}` with `kind` one of `note`, `question`, `answer`, `handoff`; `to` is a work order id or `*`. `fleetTalk.ts` exports `postMessage`, `readInbox(orderId, woId, sinceId?)` and `limitsFor`. Hard limits enforced in code: at most 6 messages sent per work order per order, at most 2 question-and-answer rounds between any pair, at most 400 characters per message, no empty text, no message to itself, no exact duplicate of the sender's previous text, no token-shaped strings (replace with `[redacted]`), and a sender must be a work order of that order. `ops/agent-msg.ts`: `npx tsx ops/agent-msg.ts send --order <id> --from <woId> --to <woId|*> --kind note --text "..."` and `npx tsx ops/agent-msg.ts inbox --order <id> --wo <woId>` (prints only messages addressed to that work order or `*` that it has not seen; remembers what was seen in a small state file beside the board). It talks to the board file directly (no server needed), prints a plain error on a limit and exits 1. In `fleet.ts`, when `FLEET_TALK=1` and the order has two or more work orders, append a short "Teammates" section to each work order's brief: the peers' ids, roles and owned files, the exact send and inbox commands with that work order's ids filled in, and two rules: run `inbox` once at the start and once just before writing REPORT.md, never in a loop, and never wait for an answer. The watcher adds one trace line (`from: "Fleet"`, `what: "worker message"`, detail: from, to, kind and the first 80 characters) per new board line, once. No live delivery into sessions in this step.

## Proof (`ops/agent-talk-check.ts`, temp COMPANY_ROOT)
PASS or FAIL per line: off by default (the brief is identical to before); post and read round trip; `*` reaches everyone but the sender; every limit refuses with a plain reason (7th message, 3rd round, 401 characters, self message, duplicate, foreign sender); a fake token is redacted; the command line tool works end to end on a temp board and `inbox` shows each message once; the brief gets the Teammates section only with two or more work orders.
## Common rules
- Create or edit ONLY the files named in "Files". Other workers are not running at the same time, but keep edits small and targeted, never rewrite an entire existing file. Match the surrounding style (ES modules, `.js` import suffixes, no new dependencies).
- Never restart or start the router. Never read, print or edit `.env` or any secret value. Never touch `company/`, Laya, Kafka or scheduled tasks. No real network calls in tests (local stubs only). No deletes of existing files.
- Default OFF behind an env flag, so existing behaviour is byte-for-byte unchanged when the flag is unset. Add the new flag name(s) to the allow-list in `src/company/envReload.ts` (small insertion) so they can be reloaded without a restart.
- Run each command ONCE, in the foreground: `npx tsc --noEmit`, then the proof script. If a step fails, report the exact error and END your turn; do not retry in a loop.
- Narrow job with an explicit end: write `docs/overnight/REPORT_<id>.md` (changed line ranges, exact command output, open issues), print the same report and END your turn. Do not wait, poll, loop, or re-read this order.
