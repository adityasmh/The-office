## Open issues / notes

- `launcherScript` needed `export` for an end-to-end proof of the generated text. That is the
  only change to it besides the insertion; behaviour is unchanged.
- `scrubList()` is the policy (flag-independent, so the deny-list can be inspected regardless of
  the switch); `launcherScrubLines()` is the gated part. Off-by-default is proven at the launcher
  level (no lines emitted, text identical to the pre-change template).
- The flag is armed by exactly `FLEET_SCRUB_ENV=1` (not `true`/`yes`), matching the order's
  spelling.
- Suffix names (`*_SECRET`, `*_PASSWORD`) are collected from the router's own env at
  launcher-generation time, which is the env the child inherits; a name that appears only after
  generation cannot exist in the child.
- `SLACK_BOT_TOKEN`, `SLACK_APP_TOKEN`, `SLACK_SIGNING_SECRET` and `NOTIFY_WEBHOOK_URL` were not
  set in the environment this proof ran in, so the live child test covered `GITHUB_TOKEN`,
  `COMPANY_AUTH_TOKEN`, `SLACK_SIGNING_SECRET`-style, `SESSION_SECRET` and `DB_PASSWORD`. The
  full default list is still asserted directly on the generated lines/list.
- PowerShell only: `launcherScrubLines("bash")` returns `[]` rather than guessing another shell
  syntax (the fleet launcher is PowerShell).
- The order restricts edits to the named files, so `ops/run-all-checks.ts` and
  `ops/checks.manifest.json` were NOT edited to register the new check.
- `ops/env-reload-check.ts` was not re-run (the order names two commands); it derives its counts
  from `RELOADABLE_ENV_KEYS.length` and still holds with 19 keys (5 present in its fixture,
  14 skipped, `unchanged === 5`).
