## Why (found in the first live run, order fomuvowd3x)
1. After publishing, the project folder stays checked out on the work-order branch `fleet/<order>/<wo>`. The next order then branches from that branch and its PR would include the earlier commit. The helper must return the folder to the branch it started on (success or failure).
2. When anything after the branch is created fails (for example the PR call returns 403), `publishWorkOrder` returns `{skipped: reason}` and `publishPass` in `src/company/fleet.ts` ignores every `skipped` result silently. A failure after a push must be visible in the order trace.
3. The commit message and the PR title are the whole order text, which can be very long.
